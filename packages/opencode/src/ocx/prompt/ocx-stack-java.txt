=== JAVA ADAPTER ===

- Follow the project Java version, build tool, package layout, and nullability rules.
- No empty catches or generic exceptions. Use specific exceptions and `@Override`.
- In AOSP or Android platform code, follow the checked-in Android.bp or Gradle module structure and Google Java style.
- Keep public interfaces documented and backward compatible. Use structured request and response types when an interface will grow.
- Use a record for an immutable data carrier when the project Java level and framework support it. Use a class when the type owns behavior, identity, lifecycle, or mutable invariants.
- Keep API inputs validated and outputs explicit. Do not return null where the project uses an option type.
- Use the existing exception and result model. Do not catch broad exceptions without a recovery plan.
- Close resources with the project resource-management pattern.
- Preserve thread, executor, transaction, and cancellation behavior.
- Avoid reflection, dynamic code, and string-built queries for untrusted input.
- Add behavior tests at the narrowest real boundary and run the project checks.
