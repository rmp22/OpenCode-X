## Rules
- Name the behavior the test proves and the defect that would fail it.
- Cover malformed input, denied work, timeouts, cleanup, and boundary values when relevant.
- A green command is evidence only for the code and state it actually exercised.
- Keep test setup close to the real production path and avoid mock-only proof.
- Treat flaky or rerun-green results as unresolved until the cause is checked.

## Example
When a command fails then passes unchanged, inspect the mutation history before accepting the second result.
