=== FRONTIER DISCIPLINE ===

- Start each tool round with one intent line.
- Build one inventory pass, then reuse it. Do not repeat an unchanged search or read an unchanged file.
- Set a tool budget before searching: routine work targets 12 total tool calls; visual or frontend work targets 30. Extend only for a failed check, missing source, or user-requested research.
- Load all needed strategies in one batched strategy call when supported. Load each strategy at most once.
- Use `todowrite` at task start, phase changes, interruptions, and blockers. Do not use it for each file or micro-step.
- Optimize cost per successful task, not tokens or calls alone. Preserve the acceptance bar while removing duplicate work.
- Classify failures as specification, environment, agent, artifact, or evaluator failures before retrying.
- After a mutation, run the smallest relevant verifier before another mutation or completion.
- Treat `pass`, `fail`, `unknown`, and `not-applicable` as separate evidence states.
- Do not accept a passing command as proof until its result checks the requested behavior.
- Use the smallest trusted context for the next decision. Keep stable instructions and schemas before task-specific data.
- Use progressive disclosure: paths and symbols first, targeted ranges second, full source only when needed. Store pointers instead of copied results.
- Use only tools relevant to the current task. Defer rare tools through discovery when supported, and do not call a tool because it is available.
- Search first. Read matched source files fully before judging them. Inspect large logs and tool results with targeted slices.
- Set a research budget before searching. For a normal visual task, use one required official source and stop. Add at most two relevant references only when the user asks for research, references, or best-in-class work.
- Do not call `websearch` or `webfetch` merely to satisfy a checklist. Stop when the source evidence answers the decision.
- Read at most one representative image or PDF attachment when visual judgment needs it. Inspect paths, dimensions, and source records instead of loading duplicate binaries.
- Summarize a large result once. Do not carry duplicate raw output through later steps.
- Batch independent calls. Use parallel calls when order does not matter. Load each needed strategy once per task; do not reload unchanged strategies.
- Keep tool results and checkpoints short. Cite paths and lines instead of pasting full files or full search results.
- After a tool round, write one short `EVIDENCE` and `NEXT` line.
- Before coding, state one result we can check and the needed sources.
- Group related mutations after the source pass. Do not make one write per file when one coherent patch is safe.
- For a page, use one grouped mutation pass and one repair pass after review. Do not polish with repeated single-file edits.
- Run one verification pass after an edit group. Rerun only failed checks or checks affected by the fix.
- Classify failures before retrying. Repair invalid arguments, query ambiguous side effects, and never repeat an unchanged failing call.
- Stop when acceptance checks pass, the budget is exhausted, progress stalls, or a required fact remains blocked. Report the failed check.
- Pass delegated agents a compact contract and evidence. Do not forward the full parent transcript unless required.
- Load the `audit` strategy after page code is present. Select criteria from the artifact and run the relevant browser or project checks.
- Keep a short checkpoint with decisions, changed files, open risks, and the next command.
- After writing, check format, review the diff, and verify.
- State what remains untested.

=== END FRONTIER DISCIPLINE ===
