=== WEB DESIGN ADAPTER ===

- Treat the product, audience, content, and available assets as facts to verify.
- Do not invent customer names, reviews, usage counts, awards, security claims, or product results.
- Do not use a fake dashboard, fake chart, fake cursor, or fake terminal as proof.
- Make every visible action reach a real handler, link, form, or documented disabled state.
- Use semantic HTML before adding JavaScript behavior.
- Make keyboard order, focus, labels, errors, and status changes observable.
- Test narrow, wide, touch, keyboard, reduced-motion, empty, loading, error, and disabled states.
- Give the page a clear visual reason to exist. Do not copy a common landing-page template.
- Record one direction, three decisions that make it distinct, and one rejected category pattern before page code.
- If a source or fetch fails, use alternate official, regional, press, content-pool, licensed, or trusted primary sources. Do not stop after one failed URL.
- Use real media when available. If it remains unavailable, use a verified contextual image or an honest unavailable state. Never draw a named product with CSS.
- Do not repeat the same promise in the hero, cards, testimonials, and footer.
- Prefer specific, truthful copy over slogans that hide missing product behavior.
- Load `fonts` for typeface choice and script coverage, then apply the CSS delivery rules below.

RTL AND LTR
- Set `lang` and `dir` on the document and propagate direction through portaled menus and popovers. Do not change the locale just to force RTL.
- Flexbox and Grid already follow `dir`; do not add `row-reverse`, CSS `order`, or reversed markup just to mirror a layout.
- Use logical CSS properties for layout: `margin-inline-start`, `inset-inline-end`, `border-inline-end`, `text-align: start`. Keep physical offsets for genuinely physical placement.
- Put `dir="auto"` or `<bdi>` around unknown mixed-direction text; keep code, URLs, IDs, and paths LTR.
- Use logical arrows and chevrons for back, forward, previous, and next. Do not mirror brands, clocks, media controls, charts, or text.
- In RTL, `scrollLeft` can start at 0 and go negative. Prefer `scrollIntoView({ inline: "nearest" })` or a tested direction-normalizing helper.
- Map interactions through direction: `clientX` stays physical; a logical-edge resize needs a direction-aware delta; logical previous/next keyboard controls may swap ArrowLeft/ArrowRight. Follow the WAI-ARIA widget pattern for the control.
- Verify behavior, not only screenshots: computed styles, pseudo-element geometry, hit zones, focus order, keyboard behavior, submenu direction, zoom, and both LTR and RTL scroll endpoints.
- Test English + LTR, English + forced RTL, one real RTL locale, and mixed RTL/LTR content with long labels, numbers, code, and paths, plus 200% text resize and the text-spacing overrides of WCAG 1.4.12.

FONT DELIVERY
- Load only needed weights and optical sizes. Use WOFF2 with `font-display: swap`, or a documented equivalent, and fallback stacks with similar letter sizes.
- For a named brand, confirm the font source and license before use; when that is not possible, record `UNVERIFIED:` and use a documented fallback. Never log an invented brand font.
- Do not fake required scripts with CSS: no drawn letters, ligatures, or diacritics, no reversed Latin, and no fake Arabic or Hebrew shapes.
