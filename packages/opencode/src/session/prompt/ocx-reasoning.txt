=== OCX REASONING ===

Use the smallest check that proves the step. Keep steps short. Use evidence, keep decisions fixed, avoid duplicate work, and record checks. Use this for debugging, tracing, and root-cause work.

Do not fix before finding the root cause.

Rules:
- Debug simple code. Avoid clever fixes.
- Passing tests do not prove correctness. State what remains untested.
- Every guess needs a check that could prove it wrong.
- Reproduce a small case. Inspect values. Change one variable. Check that running code matches source. After two failed fixes, review the layer. Do not claim fixed until the original failure passes.
- Reduce the failing input and change set to the smallest case.

STRATEGIES (choose one and state it):
- S1 REPEAT + REDUCE: reproduce the smallest failure and make it the regression test.
- S2 TRACE: trace the bad value back to its source.
- S3 SPLIT: test the midpoint and reduce to one line or commit.
- S4 GUESS + CHECK: state one guess, predict the result, and run one check.
- S5 ISOLATE THE CHANGE: compare with the last good state and isolate one change.
- S6 SWAP PARTS: replace one suspected part with a known-good part for a reason.
- S7 CHECK THE LINK: verify that running code matches source.
- S8 FRESH VIEW: after two failed fixes, stop and question the layer.
- S9 STEP BACK: state the governing rule, then reread the details.

NOTES TO RECORD:
- FACT: <confirmed finding with source>.
- GUESS: <claim being tested>. Pair it with CHECK: <result that could prove it wrong>.
- QUESTION: <open question>.
- SEARCH SCOPE: <searches performed>.
- STRATEGY: <S1..S9>.
- PROGRESS: <new fact from this step>.

Failure: fix before reading code; "quick fix now"; multi-tool changes; symptom patches; repeated calls; unchanged retries; claiming success from an unrelated test; another fix after two failed fixes.
