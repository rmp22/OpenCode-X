=== REVIEW COMMON ===

[blocker] Read all references to removed or renamed symbols. Check imports, signatures, paths, and module links.
[blocker] Resolve size, limit, math, empty value, time, lifetime, failure, and security cases touched by the change.
[warning] No wildcard imports, comments, stubs, TODOs, FIXMEs, placeholders, dead names, or duplicate lines.

=== REVIEW STRUCTURE ===

[blocker] Larger changes have clear ownership. Entry files coordinate. Focused modules own one job, state, actions, errors, resources, and tests.
[blocker] The file and module tree was defined before the first change. Do not accept one large file with a future split plan.
[blocker] Reuse the existing tools and module links. Do not add a framework or generated wrapper only to split files.
[warning] Keep repeated behavior, data, resources, configuration, and transformations in one source.
[warning] Do not keep unrelated domains in one large file or split trivial code into one-file-per-function wrappers.
[blocker] For multi-file changes, the final file tree matches the recorded `FILE PLAN`, and every changed or new file has one owner, one responsibility, a caller, and a checkable public boundary.
[blocker] The final dependency direction and state owner match the plan. No new cycle, duplicate source of truth, orphan file, parallel helper, or hidden cross-module state exists.
[blocker] When the task builds a screen, apply the loaded `ui` strategy before accepting the result.
[warning] A modular split is justified by responsibility and change locality, not by line count or a target number of files.

=== REVIEW CODE ===

[blocker] Apply the loaded language rules. No FQNs, wildcard imports, generic catches, discarded errors, or unchecked results.
[blocker] Every new API call matches its declared signature. Every external input has validation, escaping, or an allowlist at the boundary.
[blocker] Generated imports, APIs, dependencies, claims, and configuration are verified against source or primary documentation.
[blocker] Tests have an explicit behavior oracle and cover relevant negative, boundary, timeout, permission, concurrency, cleanup, and rollback cases. Coverage alone is not proof.
[blocker] Each reported success maps to a command, source path, observed state, or artifact. A tool success alone is not evidence of behavior.
[blocker] Required checks are labeled `pass`, `fail`, `unknown`, or `not-applicable`. Unknown checks are not silently accepted as pass.
[blocker] Tests assert the production behavior and could fail for the reported defect. Do not accept assertion-free, mock-only, or self-serving tests.
[blocker] Security, dependency, secret, and generated-artifact checks run when relevant, or the untested area and exception owner are recorded.
[warning] Generated artifacts come from source. Delete scratch and backup files.

=== REVIEW AI-SLOP RISKS ===

[blocker] No hallucinated imports, APIs, config keys, dependencies, claims, or placeholder success. Verify each against source or documentation.
[blocker] Changed code fits its callers, state, lifetime, errors, storage, permissions, and module links. Do not accept an isolated happy-path implementation.
[blocker] Reviewers can explain each changed boundary, rule, failure path, and check. A passing build is not proof of understanding.
[blocker] Partial completion, placeholder values, dead code, repeated logic, and unrequested behavior are removed or explicitly reported.
[blocker] No fake data, invented API or dependency, silent fallback, empty catch, phantom change, or unsupported claim remains.
[blocker] The final summary matches the final diff and executed checks. It does not claim work from an earlier state.
[warning] Reject guessed setup, too many files, pass-through wrappers, duplicate setup, generic envelopes, and textbook code that does not fit the project.
[warning] Reject broad diffs, unrelated refactors, generated files, and new dependencies without a named requirement.

=== REVIEW RESULT ===

[blocker] Resolve blockers. Resolve warnings or record the debt before delivery.
